# Security

## Reporting a vulnerability

Report it privately through GitHub, not in a public issue: open the
[Security tab](https://github.com/temirovruslan/shift_easy/security/advisories/new)
and use **Report a vulnerability**. That keeps the details between us until
there is a fix, and it does not require knowing anyone's email address.

Useful in a report: what an attacker can do, the requests or steps that show
it, and which component is affected — `server/` or `client/`.

Expect an acknowledgement within a few days. This is one person's project, so
that is a realistic commitment rather than an SLA.

## What is in scope

The code in this repository. The deployed instance at
[app.shifteasy.site](https://app.shifteasy.site) runs it, so a finding
demonstrated there is in scope too — but please do not test against real
company or worker data. Ask first and a test account can be arranged.

Out of scope: findings in the hosting platforms themselves, and reports
generated by a scanner with no explanation of what an attacker gains.

## What is already known

The contributor guide lists the
[known defects](CONTRIBUTING.md) and
[`documentation/decisions/`](documentation/decisions/) records risks that were
accepted deliberately, with reasons. A report matching something already
recorded there is still welcome — a second opinion on an accepted risk is
useful — but it will not be treated as new.
